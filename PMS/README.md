# PMS System

> 스택 가정: Spring Boot(Kotlin) + JPA, PostgreSQL. OMS 쟁점 6, 7번에서 분리됨. 범위는 `docs/scope.md` 2절 PMS.

## 1. 역할

상품이 무엇인지에 대한 정본. OMS, WMS, TMS는 `(sku_id, sku_version)`만 참조한다(OMS 7).

| 맡는 것 | 쓰는 쪽 |
|---|---|
| SKU 마스터(이름, 셀러 SKU 코드, 바코드) | 전부 |
| 채널 상품 매핑(채널 상품, 옵션 -> SKU 또는 세트) | OMS P2 정규화 |
| 세트 구성(구성품, 수량, 신고가 비율) | OMS P2, 세트 분할(OMS 7) |
| 통관 정보(HS 코드, 영문 품목명, 원산지, 신고가) | OMS P3 검증, TMS 통관 서류 |
| 실측 무게와 크기(WMS가 재서 이벤트로 보냄) | WMS 박스 선정, TMS 운임 |
| 취급 속성(파손 주의, 위험물, 유통기한 관리 여부) | WMS 보관, 피킹 |

## 2. 쟁점

| # | 쟁점 | 핵심 질문 | 결정 |
|---|---|---|---|
| P1 | 상품 식별 | `sku_id` 전역. 셀러 SKU 코드 유일 범위, 바코드 여러 개 허용 여부 | **[S1]** 셀러 SKU 코드는 셀러 안에서 유일(`(seller_id, seller_sku_code)` UNIQUE). 바코드는 SKU 하나에 여러 개(`sku_barcode`) |
| P2 | 버전 모델 | 어떤 필드 변경이 새 버전을 만드나, 표시용 수정도 버전인가 | **[S1]** 출고, 통관에 영향 주는 필드(무게, 크기, HS 코드, 신고가, 세트 구성, 취급 속성)가 바뀌면 새 버전. 기존 버전은 불변. 표시용 필드(상품명 오타, 설명)는 버전 없이 수정. 테이블 = `sku`(불변 식별, 현재 버전 포인터, 표시용 필드) + `sku_version`(PK `(sku_id, version)`, 버전 대상 필드, 생성 시각, 생성 주체, 원인) + `sku_barcode`. 주문은 수집 시점의 현재 버전을 참조하고 이후 버전을 따라가지 않는다. 예외(신고값과 실측값 차이가 클 때)는 P5 |
| P3 | 채널 매핑 | 매핑 버전 관리, 매핑 실패 -> OMS 보류, 한 채널 상품 -> 여러 SKU(세트) 표현 | **[S1 매핑 키, 대상 하나 / S3 매핑 실패 보류 / S5 이력, 자동 매핑]** 매핑 키 = `(channel, seller, channel_product_id, channel_option_id)` -> 대상 하나(`SKU` 또는 `SET`, `target_id`). 매핑은 버전을 고정하지 않고, 버전은 수집 시점에 `pms_sku_current`로 정한다(P2). 채널 옵션 하나가 여러 SKU로 가면 그 구성을 세트로 등록해 세트를 가리킨다(구성 표현은 P4 한 곳). 매핑 이력 `channel_mapping_history`(유효 시작, 유효 끝, 변경 주체)는 감사용, 주문에 적용된 결과는 OMS `order_line`에 남는다. 등록 = 셀러 직접 또는 일괄 업로드, 채널 옵션의 셀러 SKU 코드가 PMS 셀러 SKU 코드와 정확히 일치하면 자동 매핑. 실패 = OMS 보류 + 자동 전환(P7) |
| P4 | 세트 | SKU의 한 종류 / 별도 엔티티, 구성 변경 시 버전 | **[S4]** 세트 = `sku`의 종류 `SET`. 구성품 `set_component`(구성 SKU, 수량, 신고가 비율)는 세트의 버전에 속하고, 구성이 바뀌면 세트의 새 버전(P2) |
| P5 | 실측 값 | 신고값, 실측값 둘 다 보관 여부, 실측 반영 시 새 버전 여부, 오차 클 때 처리 | **[S1 신고값 / S4 실측값, 새 버전 / S5 오차 경보]** `sku_version`에 신고값과 실측값을 둘 다 둔다. WMS 실측 이벤트가 오면 새 버전, 실측값이 있으면 실측값 우선. 오차가 클 때 경보, 셀러 정산은 v2 후보 |
| P6 | 통관 정보 | HS 코드 6자리(국제 공통) / 국가별 10자리, 누락 시 OMS 보류 연결 | **[S4]** HS 코드 6자리 + 영문 품목명 + 원산지 + 신고가를 `sku_version`에. 누락이면 OMS 보류 사유 "통관 정보 누락"(OMS 12). 국가별 10자리는 v2 후보 |
| P7 | 다른 시스템에 전달하는 방식 | 동기 조회 API + 캐시 / 이벤트 복제. 버전 불변 = `(sku_id, version)` 캐시 영구 유효 | **[S1 불변 조회 + 캐시, 복제 테이블 / S2 순번 / S3 자동 전환 / S5 스냅샷 보정]** 데이터 성질로 나눈다. **불변 데이터**(`(sku_id, version)` 상세) = 캐시에 없을 때만 PMS 동기 API 조회, 로컬 캐시에 무기한 보관(무효화 없음). **바뀌는 포인터**(채널 매핑, SKU 현재 버전) = PMS가 outbox로 이벤트 발행, 받는 쪽이 복제 테이블 보유. OMS 복제 = `pms_channel_mapping`(채널, 셀러, 채널 상품, 옵션 -> SKU / SET, 대상 ID, `pms_seq`. 버전은 P3대로 두지 않음), `pms_sku_current`(SKU -> 현재 버전, `pms_seq`). 순번이 큰 이벤트만 반영, 주기 스냅샷으로 보정(OMS 15와 같은 방식). WMS, TMS는 주로 불변 데이터라 조회 + 캐시. **매핑 실패 자동 전환**: OMS 매핑 실패 보류(OMS 12)에 기다리는 매핑 키(`wait_key`)를 적는다. 해당 매핑 이벤트가 도착하면 보류를 실패에서 해제로 전환(해제 주체 = 시스템, 해제 시각, 원인 이벤트 ID `release_cause_message_id`)하고, 프로세스 모듈(OMS 18) 단계 기록에 P2 재진행을 원인 이벤트와 함께 남긴 뒤 P2부터 다시 진행. 전환 기록은 `order_hold` 행 자체와 `order_process_step`이 맡는다(OMS ERD 반영) |
| P8 | 취급 속성 범위 | v1 플래그만 / 로트, 유통기한까지(WMS와 맞물림) | **[S1]** 플래그만(파손 주의, 위험물). 로트, 유통기한은 v2 후보 |
