# 범위 지도

> OMS, WMS, TMS 전체에서 무엇을 다루고 무엇을 미루는지 한곳에 모은 문서. 시스템별 상세 쟁점은 각 폴더 README에 둔다.

## 1. 이 프로젝트의 OMS는 어떤 OMS인가

OMS라는 이름은 두 종류에 같이 쓰인다. 어느 쪽인지에 따라 "할인", "등급"이 OMS 일인지가 갈린다.

| | 커머스 OMS (자사몰 내부) | 풀필먼트 OMS (물류사, 3PL) |
|---|---|---|
| 고객 | 최종 구매자 | 셀러(화주) 여러 곳 |
| 주문 출처 | 자기 몰 하나 | 여러 채널, 여러 셀러 |
| 가격, 할인, 등급 | 직접 계산 | **채널이 확정한 값을 받아 스냅샷으로 저장** (통관 신고가, 정산에 씀) |
| 사은품 | 프로모션으로 직접 결정 | 셀러가 정한 룰로 출고 품목에 추가 |
| 배송 서비스 | 직접 결정 | 채널이 받은 선택(당일, 일반, 특송)을 서비스 레벨로 매핑 |

이 프로젝트는 루트 README의 문제 설정(여러 채널, 셀러, 해외 출고) 기준으로 **풀필먼트 OMS**로 본다. [결정 2026-10-30]

- 등급별 할인 계산: 범위 밖 (채널 책임). OMS는 할인 반영된 금액과 등급 같은 플래그를 받기만 한다.
- 등급에 따른 배송 업그레이드: 채널이 서비스 레벨로 보내거나, 셀러 룰("VIP 플래그 -> 특송")로 OMS가 바꾼다. 후자는 룰 엔진 범위.

## 2. 기능 지도

단계: **1** = 도메인, ERD에 넣는다 / **2** = 구조만 잡고 동작은 실험 단계에서 / **설계만** = 개념과 데이터 모델만 정리, 구현 안 함 / **밖** = 이 프로젝트에서 다루지 않음.

### OMS

| 기능 | 단계 | 메모 |
|---|---|---|
| 채널 주문 수집, 멱등 | 1 | |
| 정규화, SKU 매핑, 세트 분해 | 1 | |
| 주소 정규화, 권역 판정 | 1 | 국가, 우편번호 -> 권역. 배송 불가 지역, 도서산간 |
| 배송 서비스 레벨 (당일, 일반, 특송) | 1 | 마감 시간, 창고 선택, 운송 서비스에 다 걸림 |
| 검증 (필수값, 통관 정보) | 1 | |
| 셀러 룰 엔진 | 1 | 룰 저장 형태와 적용 기록. 룰 종류 확장은 2 |
| 사은품 | 1 + 2 | 테이블은 1. 선착순 수량 한정은 동시성 문제라 2 |
| 보류, 사람 확인 | 1 | |
| 합치기(합포장), 나누기 | 1 | |
| 다중 창고 할당 (가까운 창고 등) | 1 + 2 | 기준과 결과 기록은 1. 알고리즘 비교는 2 |
| 주문 우선순위 | 1 | 마감 임박, 서비스 레벨, 셀러 등급 |
| 주문 상태, 이력 | 1 | |
| 취소, 변경, 부분 취소 | 1 | |
| 채널 회신 (송장, 상태) | 1 | |
| 채널 재고 동기화 (품절 반영, 오버셀 방지) | 2 | 빠지면 없는 재고가 계속 팔림 |
| 반품, 교환 (RMA) | 2 | OMS 접수 -> WMS 입고 검수 -> 재고 복귀 또는 폐기 |
| 가격, 할인, 등급 계산 | 밖 | 1절 |
| 결제 | 밖 | 채널 책임 |
| B2B 대량 주문 (품목 수천 줄) | 밖 | B2C 기준으로 주문 애그리거트를 설계 (OMS 5번) |

### PMS (Product Management System, 상품 관리)

OMS 쟁점 6번에서 분리하기로 결정(2026-10-31). PMS가 상품의 정본이다. OMS, WMS, TMS는 `(sku_id, sku_version)`만 참조한다. PMS는 수정 시 새 버전을 만들고 기존 버전은 고치지 않는다.

| 기능 | 단계 | 메모 |
|---|---|---|
| SKU 등록 (셀러 SKU 코드, 상품명, 영문명) | 1 | |
| 통관 정보 (HS 코드, 원산지, 기본 신고가), 위험물 | 1 | |
| 세트 구성 | 1 | |
| 채널 상품 매핑 | 1 | OMS 정규화가 조회 |
| 실측 무게, 크기 | 1 | WMS가 입고 때 재서 이벤트로 PMS에 반영 |
