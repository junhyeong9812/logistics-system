# TMS System

> 스택 가정: Spring Boot(Kotlin) + JPA, PostgreSQL. 상세 정리는 OMS 다음 순서에 한다. 지금은 OMS 논의에서 먼저 정해진 것만 적는다.

## 쟁점 (선결정)

| # | 쟁점 | 결정 |
|---|---|---|
| T1 | 배송망 모델 | 출고 건을 구간(leg) 단위로 모델링한다. `shipment` 1 : N `shipment_leg`(순번, 출발 거점, 도착 거점, 운송 수단, 수행 주체 = 외부 운송사 / 자체 차량, 운송장 또는 운행 ID, 상태). `node` 종류 = 창고 / 허브 / 수출 거점 / 운송사 인계 지점 / 수취인. **v1 구현 = 외부 운송사 구간 1개(창고 -> 수취인)만**. 자체 배송망(허브, 간선 일정, 배차, 기사 앱)은 설계 수준으로만 정리하고 v2 후보로 둔다. 테이블 자리는 v1부터 만든다 |
| T2 | 배송 추적 | 추적 대상의 정본은 DB 테이블(`tracking_shipment`: 운송장 번호, 운송사, 현재 상태, `next_poll_at`, 마지막 이벤트 시각). 메모리에 두지 않는다. 운송사 webhook 우선, 조회는 webhook 없는 운송사와 누락 보정용. 스케줄러가 `next_poll_at`이 지난 행만 골라 운송사별 큐로 보내고 워커가 조회. 조회 간격은 상태별(운송 중 드물게, 도착 예정 근처 자주), 종료 상태(배송 완료, 반송 완료)면 제외. 간격 수치와 운송사별 호출 한도는 미정 |
| T3 | 도착 예정일 | TMS가 리드타임 표 `(출고 창고, 운송사 서비스, 목적지 권역) -> 운송 일수(최소, 최대)`로 계산. 도착 예정 = 출고 기한 + 운송 일수(영업일 캘린더). 일 단위, 추적 이벤트로 보정. 시간 단위 예정은 v1 범위 밖(자체 배송망 구간이 생기면 구간별 소요 시간 합으로) |

## 자체 배송망 (B, 설계 수준)

크로스보더에서 자체 운영이 가능한 범위는 국내 구간이다.

```text
창고 -> (자체 간선) -> 국내 허브 -> (자체 간선) -> 수출 거점(공항, 항만) -> [국제 운송사] -> 현지 통관 -> [현지 운송사] -> 수취인
        └──────────── 자체 운영 가능 (B) ────────────┘   └──────────────── 운송사에 맡김 (A) ────────────────┘
```

| | 창고 (풀필먼트 센터) | 허브 (분류 거점) |
|---|---|---|
| 하는 일 | 재고 보관, 피킹, 패킹 | 분류, 다음 구간으로 넘김 (보관 안 함) |
| 머무는 시간 | 며칠~몇 달 | 몇 시간 |
| 시스템 | WMS | TMS (B에서만) |
